修复 bat 文件编码事故 + 通知文案 + 清理完成消息

【事故：终端无限刷屏】
现象（用户报告）：
    '_URL" >nul' 不是内部或外部命令，也不是可运行的程序
    '彲鑳芥槸宕╂簝鎴栨墜鍔ㄥ叧闂級銆?echo' 不是内部或外部命令...
    系统找不到指定的路径。

根因（两层）：
1. **bat 文件是 UTF-8 + 中文，但系统代码页是 936(GBK)**
   原文件开头有 `chcp 65001`，看起来应该够 —— 但 cmd.exe
   **在解析到 chcp 那一行之前，就已经按系统代码页解读了文件**。
   UTF-8 的中文字节被当 GBK 解析 → 乱码 → 命令破碎。
   （奇怪的是它之前能用，所以这个问题对编辑方式很敏感）

2. **我改文件时没显式指定编码**
   用 Python 写文件时漏了 encoding 参数，在某些路径下按系统默认(GBK)
   写入，而内容是 UTF-8 中文 → 文件编码进一步错乱。

【修复方案：bat 里一个中文都不放】
  - 整个 bat 改成**纯 ASCII**（title/echo 都用英文）
  - 通知的中文文案移到 notify_content.txt（UTF-8）
  - bat 用 curl 的 `--data-urlencode "desp@文件"` 语法读文件
  - 写文件时用 `open(..., encoding='ascii')` 强制校验，
    一旦混入非 ASCII 字符会立刻抛错，防止再犯

  现在：非 ASCII 字节 = 0，cmd 无论按 GBK 还是 UTF-8 解析都一致。

【教训记录】
  ⚠️ **Windows 批处理文件里不要放非 ASCII 字符**，
     除非确定 cmd 的解析代码页。最稳妥是纯 ASCII + sidecar 文件。
  ⚠️ Python 写文件**必须显式指定 encoding**，否则 Windows 下可能
     按 GBK 写入，把 UTF-8 内容搞坏。写 ASCII 内容时用
     encoding='ascii' 能自动防错。
