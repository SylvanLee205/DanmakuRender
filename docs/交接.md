## 一、30 秒理解这套系统

一台 Windows Server 上跑着的**无人值守直播归档系统**（项目名 **DanmakuRepo**，
缩写 **DMR** —— 所以代码包名 `DMR/`、配置键 `dmr_engine_args`、日志前缀
`DMR-*.log`、桌面脚本 `DMR-*.bat` 全都是这个缩写，不要以为是两个项目。
项目目录名仍是 `F:\DanmakuRender_AutoUp`，有意不改，原因见 README 第四节）：

```
33 个主播轮询（抖音为主）
   ↓ 开播了
ffmpeg 拉流录制（ts 分段，每小时一段）
   ↓ 下播
渲染弹幕版 mp4（.ass 字幕烧进视频）
   ↓
上传百度网盘（rclone → CloudDrive2）
   ↓ 24 小时后
删源视频 + 源弹幕（弹幕版永久保留）
```

**它已经连续运行数月，中间崩过、蓝屏过、被限速过，都修了。**
你现在看到的是踩完坑之后的版本。

**三个最重要的文件/目录**：

| 路径 | 是什么 |
|---|---|
| `configs/global.yml` | 全局配置（git 忽略，含个人化参数）。**改动必须重启才生效** |
| `logs/dmr_state.db` | SQLite 状态库。哪些分段录完/传完/清完，重启不丢 |
| `直播回放/<主播>/` | 源视频（24h 后自动删）；`（弹幕版）` 子目录是永久保留的成品 |

## 二、怎么跑起来

```bash
# 1. 依赖（注意：比上游原版多了 rclone/psutil/fonttools）
python -m venv .venv && .venv\Scripts\pip install -r requirements.txt

# 2. ffmpeg 放进 tools/ 或加入 PATH

# 3. 启动（Windows）
Start_DMR.bat
```

启动后会看到三层自启体系（已配好，正常情况下你不用管）：

1. **Startup .cmd** —— 登录时自启，交互式，**有可见窗口**
2. **SessionWatch 计划任务** —— 登录+解锁触发，负责跨会话迁移
3. **Boot 计划任务** —— 开机启动，session 0 常驻守护，无人登录时兜底

**验证跑起来了**：

```bash
python tools/dmr-status.ps1        # 状态面板
# 或看日志尾部
tail -f logs/DMR-*.log
```

## 三、日常操作（你 90% 的时间只需要这些）

| 想干什么 | 怎么做 |
|---|---|
| **加主播** | 复制抖音直播间链接 → 双击桌面 `DMR-添加主播.bat`。自动取名、写配置、**热加载不用重启** |
| **看状态** | 双击 `DMR-看实时日志.bat`，或 `python tools/dmr-status.ps1` |
| **停用某个主播** | 两步：① `configs/DMR-xxx.yml` 挪进 `configs/temp/` ② `python tools/purge_task_state.py --apply`。**只做①会启动失败** |
| **重新启用** | 把配置从 `configs/temp/` 挪回 `configs/`（热加载）。历史状态没了，上传记录要重走 |
| **改全局配置** | 改 `configs/global.yml` → **重启 DMR** |
| **重启** | `python tools/stop_dmr.py`（优雅停止）→ `Start_DMR.bat` |
| **推送代码** | 双击桌面 `DMR-推送GitHub.bat` |

**桌面脚本清单**（都在 `C:\Users\Administrator\Desktop\`）：

```
DMR-启动.bat          拉起 DMR（已在跑会安全跳过，不会双开）
DMR-停止.bat          优雅停止
DMR-看实时日志.bat     滚动日志 + 定期状态行
DMR-添加主播.bat      剪贴板链接 → 新任务
DMR-重启后检查.bat     重启后自检（自动登录四要素、窗口可见性）
DMR-推送GitHub.bat    推 prod-sync 到公开仓库
DMR-更新完整副本.bat   同步完整副本到私有仓库
DMR-仓库改名.bat       GitHub 仓库改名
```

## 四、踩坑与注意事项（**最重要的一节**）

按"会不会咬人"排序。前五个都实际造成过事故。

### 1. 改 `DMR/` 下的代码必须重启才生效
配置热加载**只覆盖 configs/**，不覆盖代码。这个坑踩过三次 ——
改完代码不重启，以为修好了，其实跑的还是旧代码。

### 2. 改 `configs/global.yml` 同样必须重启
DMR 检测到 global.yml 变化只会打一行警告"需要重启程序才会生效"，**不会自动应用**。

### 3. 停用主播必须两步（见上表）
只把配置挪进 `configs/temp/` 会让 `_check_task_set_consistency()` 拒绝启动，
然后守护循环每 10 秒重拉一次 → **崩溃循环刷日志**。
（2026-10-23 实际发生过，26 个日志文件。）

### 4. 任务名 ≠ 录像目录名
`output_dir` 可以指向任何目录，`DMR-<任务名>.yml` 的文件名和 `output_dir`
**没有必然关系**。这个坑出现过三次：
- `DMR-迪佳奥特曼.yml` → `直播回放/我已经不会再流泪`
- `DMR-君君.yml` → 曾经是 `直播回放/jun'jun`
- `DMR-断尾人类.yml` → `直播回放/断尾人类`（这个倒是巧合一致）

### 5. 重启前先确认没有正在渲染/录制的任务
硬杀会让 ffmpeg 来不及收尾：正在录的分段停留在 `[正在录制]` 状态、
rename 不执行，正在渲染的任务半途而废。
（2026-10-30 实际丢掉过一场。）现在 `stop_dmr.py` 默认优雅停止，
但**如果你手动 kill 就没这个保护**。

### 6. `.bat` 文件必须纯 ASCII
cmd.exe 用**系统代码页（GBK）**解析 bat，`chcp 65001` 还没生效就读完了。
中文注释会让命令解析错乱 —— 表现为"双击后只弹一句请按任意键"。
这个坑 2026-10-07、10-23、11-02 各踩过一次。写完 bat 立刻校验：

```bash
LC_ALL=C grep -q '[^ -~]' xxx.bat && echo "有非 ASCII" || echo "OK"
```

### 7. `glob` 匹配不了 `[正在录制]`
方括号是 glob 的字符类语法。必须用 `os.listdir` + `startswith`。
（踩过两次。）

### 8. 上传前会校验 mp4 时长
读不出时长的 mp4 **拒绝上传**（防半成品）。所以如果你看到
"读不出时长"，先 ffprobe 确认文件是不是真的坏了 —— 有时只是探测方式的问题。

### 9. 一条 ffmpeg 断言可能对应多个不相干的原因
`Assertion ... bytewidth failed at libavutil/imgutils.c:351` 这条，
背后有三个独立真凶（无字形字符 / 彩色 emoji 字体 / 源视频损坏帧）。
**排查必须分层**：`-f null`（不编码）隔离字幕层，换编码器隔离编码层。
详见[排查记录-20261102](排查记录-20261102-渲染崩溃三个真凶.md)。

### 10. DMR 日志里的"原因判断"不可信
它只看了退出码就写"GPU 编码会话被其他程序占用"，
而实际可能是 libass 字幕帧坏。报错要回到 ffmpeg 原始输出看。

## 五、出事了怎么办

| 症状 | 原因 | 处理 |
|---|---|---|
| **DMR 起不来，日志刷 Traceback** | 大概率是状态库和配置不一致（你刚停用过主播） | `python tools/purge_task_state.py --apply` |
| **守护循环每 10 秒重拉，刷大量日志** | 同上，崩溃循环 | 先 `DMR-停止.bat` 停下，再 purge_task_state |
| **某个主播渲染反复 failed** | 弹幕字符 / hevc_qsv / 源视频损坏 | 看 `logs/DMR-*.log` 里那条渲染错误的具体 ffmpeg 输出 |
| **磁盘满了** | 源视频没被清（跳过上传的分段曾有个 bug） | `python tools/clean_skipped_backlog.py`（默认预览） |
| **`[正在录制]` 文件越积越多** | 进程被杀留下的孤儿 | `python tools/rename_orphans.py --apply`（登记后启动对账自动接管） |
| **上传失败** | CD2 / 网盘 / 网络 | 看 `logs/cd2_watchdog.log`；上传失败有 5 次重试 + 冷却 |
| **重启后没有 DMR 窗口** | 计划任务拉起的进程窗口必隐藏 | 正常。用 `DMR-看实时日志.bat` 看状态；要窗口就双击 `DMR-启动.bat` |
| **RDP 连不上（报 0x5）** | 单账号单会话被占用 | 桌面 `RDP进不去就双击这个.bat`（在 archive 相关文档里） |

**通用急救**：

```bash
# 1. 看状态
python tools/dmr-status.ps1

# 2. 看最近错误
grep "\[error\]" logs/DMR-*.log | tail -20

# 3. 重启（优雅）
python tools/stop_dmr.py && Start_DMR.bat
```

## 八、还需要知道的几件事

- **Git**：本地 `master` 是完整历史；`prod-sync` 是脱敏后的公开同步分支；
  私有仓库 `DanmakuRender-Full` 是含 `configs/` 的完整副本（灾难恢复用，
  **含主播链接，绝不能公开**）。
- **代码包名 `DMR/` 保持不变**：改它要动几百处 import 和运行中的进程路径，
  收益只是"看起来像自己的"，不值。
- **已知未修**：hevc_qsv 硬件编码不稳定（长视频可能崩，靠降级 libx265 兜底）。
  建议更新 Intel Arc 驱动。详见 [TODO.md](TODO.md)。
- **`.login_info/` 目录不存在**：DMR 全匿名跑，没有 cookie 要迁移。
