# 重启通知说明（2026-10-07）

## 一、手机收到的通知长这样

```
┌─────────────────────────────────────────┐
│ DanmakuRender 状态报告                   │  ← 标题
├─────────────────────────────────────────┤
│ DanmakuRender 已成功复活。                │
│                                          │
│ 启动时间：2026-10-07 14:47:24            │
│ 录制服务：已启动，正在监听 32 个主播       │
│ 云端通道：CD2 正常                       │
│ 近 24h 录制：7 个分段                    │
│ 正在录制：暂无（当前无主播开播）           │
└─────────────────────────────────────────┘
```

**每条信息的含义/来源**：

| 行 | 来源 | 为什么有用 |
|---|---|---|
| 启动时间 | 系统时间 | 一眼看出是什么时候重启的 |
| 录制服务：监听 N 个主播 | `config.replay_config` 实际数量 | 确认任务配置**全部加载成功** |
| 云端通道：CD2 正常 | 实时查服务状态 + 19798 端口 | **上传链路是否可用**（这是最常出问题的一环） |
| 近 24h 录制：N 个分段 | 统计 `直播回放/*（弹幕版）/*.mp4` 的 mtime | 判断录制是否在正常产出 |
| 正在录制：xxx | 从日志里读每个任务最后的 直播开始/已结束 | 知道**现在谁在播** |

**异常时会变成**：

```
标题：⚠️ DanmakuRender 频繁重启（3次/时）

DanmakuRender 已成功复活。
...
云端通道：⚠️ CD2 服务在跑但端口未监听     ← CD2 有问题时提示

⚠️ 频繁重启：最近 1 小时 3 次，请检查日志
```

## 二、为什么由 DMR 发通知，而不是 bat

| | bat 发（旧做法） | **DMR 发（现在）** |
|---|---|---|
| 时机 | 启动**前** | 启动**成功之后** |
| 能说什么 | "我要启动了" | "已经起来了，加载了 32 个主播" |
| DMR 启动失败时 | ❌ 仍报"已复活"（误报） | ✅ 不会发通知 |
| 能否带真实状态 | ❌ 什么都查不到 | ✅ 任务数/CD2/录制数都能查 |

## 三、频繁重启检测（防刷屏告警）

```
FLAP_WINDOW    = 3600   # 统计窗口：1 小时
FLAP_THRESHOLD = 3      # 超过 3 次 → 告警
MIN_COUNT_GAP  = 600    # 距上次计数不足 10 分钟不重复计数
```

**`MIN_COUNT_GAP` 为什么必要**：
调试时可能 10 分钟内手动重启好几次，如果每次都计数就会误报。
加了 10 分钟冷却后：
```
连续重启 3 次（间隔 <10 分钟） -> 只计 1 次  ✅ 不误报
隔 11 分钟再重启               -> 正确 +1    ✅ 能识别真崩溃循环
```
真正的"崩溃→自动重启"循环间隔是 10 秒 + 启动时间，远小于 10 分钟，
所以**仍然能被正确识别**。

重启历史存在 `.temp/restart_history.json`（保留 7 天）。

## 四、技术实现

**通知内容生成 + 发送**：`tools/gen_restart_notify.py`
```python
notify(task_count=32, log_file='logs/DMR-xxx.log')
  ├─ build()  生成标题 + 正文
  └─ send()   写 UTF-8 文件 → 调 curl 发送
```

**为什么中文不写进 bat**（血的教训）：
```
cmd.exe 按系统代码页(936/GBK)解析 bat 文件，
而 chcp 65001 要等解析到那一行之后才生效。
所以 bat 里的 UTF-8 中文会被当 GBK → 乱码 → 命令破碎 →
无限刷屏 '_URL" >nul' 不是内部或外部命令...
（2026-10-07 实际发生过，刷了几百行）
```
**现在 bat 是纯 ASCII（0 个非 ASCII 字节）**，中文一律走
`notify_title.txt` / `notify_content.txt` 两个 UTF-8 文件，
curl 用 `title@文件` / `desp@文件` 语法读取。

**Start_Render.bat 现在只做三件事**：
```bat
chcp 65001 >nul
F: & cd "F:\DanmakuRender_AutoUp"
".\.venv\Scripts\python.exe" main.py --quiet     rem 崩了循环重来
```

## 五、手动测试通知

```powershell
cd F:\DanmakuRender_AutoUp
.\.venv\Scripts\python.exe tools\gen_restart_notify.py
```

会打印标题和正文，并真的发一条到你手机。

## 六、想改文案？

编辑 `tools/gen_restart_notify.py` 的 `build()` 函数，
那几行 `L.append(...)` 就是正文内容。
改完不用重启 DMR，下次重启生效；想立刻看效果就手动跑一次上面的命令。
