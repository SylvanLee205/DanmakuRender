# 配置保护机制

> `configs/` 是**唯一的真实配置源**。丢了就重建不了 —— 33 个主播的
> 任务配置、上传规则、清理规则、渲染参数全都在里面。

## 一、configs 里到底有什么

```
F:\DanmakuRender_AutoUp\configs\
    global.yml          全局配置（含我们的全部魔改）
    DMR-*.yml   × 33    33 个主播的任务配置
    temp\       × 99    配置模板
    ─────────────────────
    合计 133 个文件
```

### global.yml 里的关键自定义段（缺任何一个都会出事）

| 配置段 | 作用 | 缺了会怎样 |
|---|---|---|
| `upload_args` | 上传配置（含 rclone 网盘） | **无法上传** |
| `upload_args_task_default` | 上传规则本体（`dm_video → rclone`） | **弹幕版不会上传** |
| `clean_args` | 清理规则 | 源文件不删，磁盘被塞满 |
| `render_args` | 渲染参数（GOP 等） | 渲染参数回默认 |
| `download_args` | 下载配置（分段时长、重试等） | 录制行为变化 |
| `skip_upload_rule` | 跳过上传规则（我们的魔改） | 竖屏/低质量视频全上传 |

⚠️ **特别注意 `rclone` 的 `realtime`**：
```yaml
# 你当前用的是 false（整场合并后传，网盘归档推荐）
realtime: false
```
曾被误改成 `true`（边录边传，会产生一堆碎文件）—— 这会改变上传行为。

## 二、三层防护

### 第 1 层：快照（自动，每天 04:00）

计划任务 `DanmakuRender_配置快照` 每天 04:00 生成一份快照到
`F:\_DMR配置快照\<时间戳>\`，保留最近 **20** 份。

```powershell
# 手动打快照
python tools\backup_configs.py snapshot

# 指定保留份数
python tools\backup_configs.py snapshot --keep 30

# 列出所有快照
python tools\backup_configs.py list

# 从快照恢复（恢复前会自动先备份当前状态）
python tools\backup_configs.py restore 20261015-190029
```

### 第 2 层：启动校验（自动，每次启动 DMR）

`main.py` 的 `_verify_configs()` 在起引擎之前检查：

```
配置完整性校验
  ✅ global.yml 关键段完整
  ✅ 任务配置 33 个
  ✅ 与最近快照一致（20261015-190029）
```

发现问题的输出（示例）：
```
[error] 配置缺失 2 项，**上传/清理可能失效**：
[error]     ❌ upload_args_task_default —— 上传规则本体
[error]     ❌ clean_args —— 清理配置
[error]     恢复方法: python tools\backup_configs.py list
[error]               python tools\backup_configs.py restore <快照名>
```

检查三项：
1. `global.yml` 存在 + 5 个关键段都在
2. 任务配置数量（0 个报 error，少于 10 个报 warning）
3. 和最近快照逐文件比对（用 manifest.json 的 MD5）

**校验出问题不影响启动** —— 所有异常都被兜住，只记日志。

### 第 3 层：手动校验

```powershell
python tools\backup_configs.py verify
```

输出示例：
```
对比快照: 20261015-190029（2026-10-15 19:00:29）
快照文件数: 133   当前文件数: 133
🟠 被修改 1 个文件:
    global.yml
✅ global.yml 全部关键段都在
```

会区分三类：
- 🔴 **丢失**（严重，会给出恢复命令）
- 🟠 **被修改**（需要确认是不是有意的）
- 🟢 **新增**（正常）

## 三、为什么需要这些（真实教训）

### 2026-10-15 合并上游时差点踩坑

```
错误理解：以为 configs/ 是 junction 共享目录，
         可以直接把 dev 同步到 prod。
实际：    是**独立目录**！而且：

  prod 有 3 个用户任务配置，dev 完全没有：
      DMR-TG当当.yml        (live.douyin.com/123456789)
      DMR-小玟不是小玫.yml   (live.douyin.com/123456789)
      DMR-灰蒙蒙.yml        (live.douyin.com/123456789)

  dev 的 global.yml 还丢了：
      upload_args_task_default（上传规则本体）
      clean_args（清理配置）
  而且 rclone realtime 被改成 True（改变上传行为）
```

**最终靠"只同步代码、configs 完全不动"才避开。** 但当时**没有任何机制
保证以后不踩** —— 所以才做了这套防护。

## 四、其他相关注意

- **`global.ymal`**（`.ymal` 不是 `.yaml`）：用户自己的配置文件，
  代码读的是 `global.yml`。同步时已加入排除列表。
- **`configs/temp/`**：99 个配置模板，也一起备份了。
- **恢复策略**：`restore` 会先把当前状态打一份快照再覆盖，所以恢复错了还能再恢复回来。
- **快照不含 `.venv`/`logs`/`直播回放`**，只有配置，一份约 193 KB。
