### 为什么应用版不能远程访问（推测）

两个可能原因，都指向"用户会话 vs 系统服务"的本质差异：

1. **绑定地址不同**：服务版监听 `0.0.0.0:19798`（所有网卡），
   应用版可能只绑 `127.0.0.1` 或仅本机
2. **防火墙规则落点不同**：Windows 防火墙弹窗是按程序授权的。
   服务版以 SYSTEM 身份运行，其监听更容易被系统级规则覆盖；
   用户会话程序收到"阻止"后就没有入站规则

> 注：应用版已停用，无法实测验证。以上为推断。

## 二、⚠️ 远程访问安全须知（重要）

### 现状

```
服务版监听:  0.0.0.0:19798   ← 所有网卡

实测（都不需要登录）:
  http://127.0.0.1:19798/     -> HTTP 200  title='CloudDrive'
  http://100.75.58.27:19798/  -> HTTP 200   ← Tailscale
  http://192.168.5.5:19798/   -> HTTP 200   ← 局域网
```

**问题：Web 管理界面没有任何认证。**

### 但 WebDAV 是安全的

```json
// webdav_config.json
{
  "enabled": true,
  "clouddrive_account_enabled": true,   // 需要账户认证
  "anonymous_access_enabled": false,    // 匿名关闭
  "dav_users": []
}
```

WebDAV 路径（`/dav`）需要 CloudDrive 账户名+密码：

```
rclone.conf [cd2]:
  user     = 1871163532@qq.com
  password = lisenhu666          ← ⚠️ 明文
```

### 风险评估

| 场景 | 风险 | 说明 |
|---|---|---|
| 仅 Tailscale 内可达 | 🟠 低 | Tailscale 只有你自己的设备在内。可接受 |
| 局域网内可达 | 🟠 中 | 同网段任何设备能打开管理界面 |
| **公网可达**（做了端口转发） | 🔴 **高** | **绝对不要**。管理界面无认证 = 别人能操作你的网盘 |

### 管理界面的实际权限（实测）

我探测了常见 API 路径，全部 404：

```
/api/v1/  /api/v1/fs/list  /api/fs/list  /api/v1/user
/api/v1/config  /api/config  /api/v1/mount  /api/v1/task
```

**但界面引用的 JS 里有 `remote-upload-helpers.js`、`qr-code-helpers.js`** ——
说明界面上确实有操作功能（远程上传、扫码登录等）。
**API 路径没被猜到，不等于没有。**

### 建议

1. ✅ **用 Tailscale 远程访问没问题**（加密、私有网络）
2. ❌ **绝对不要**在路由器上给 19798 做端口转发
3. 🟠 如果局域网里设备杂（合租、公司网），考虑用防火墙限制 19798
   只允许 Tailscale 网段：
   ```powershell
   # 只允许 Tailscale 的 100.64.0.0/10 访问 19798
   New-NetFirewallRule -DisplayName 'CD2-WebUI-TailscaleOnly' -Direction Inbound `
     -LocalPort 19798 -Protocol TCP -Action Allow -RemoteAddress 100.64.0.0/10
   New-NetFirewallRule -DisplayName 'CD2-WebUI-BlockLAN' -Direction Inbound `
     -LocalPort 19798 -Protocol TCP -Action Block -RemoteAddress LocalSubnet
   ```
   ⚠️ 加之前先确认别把自己锁在外面（rclone 走 127.0.0.1，不受影响）
4. 🟠 定期检查是否有陌生设备访问（`enable_access_log` 目前是 false，可开）

## 三、日志降噪（2026-10-07 实施）

用户反馈："终端的输出有点乱，信息也有点多，看不过来"。

### 改动

**main.py 新增 `--quiet` 参数：**

```python
parser.add_argument('--quiet', nargs='?', const='quiet', default=None,
                    metavar='LEVEL',
                    help='降低控制台输出。不带值 = 只显示 WARNING 及以上；'
                         '也可指定 info/warning/error/debug。'
                         '注意：只影响控制台，日志文件始终保留全部 DEBUG。')
```

**级别映射：**
```
不带 --quiet         -> INFO（原行为）
--quiet             -> WARNING（只留警告和错误）
--quiet=error       -> ERROR（只留错误）
--quiet=debug       -> DEBUG（排查用，很吵）
--quiet=乱填         -> WARNING（回退）
```

**关键保证：日志文件（`logs/DMR-日期.log`）永远是 DEBUG，不受影响。**
所以降噪不会丢失排查能力 —— 出问题去看日志文件就行。

**启动横幅**（用 `print` 直出，任何级别都显示）：
```
====================================================================
  DanmakuRender-5 5.x.x   已启动
  控制台输出级别: WARNING(安静)
  完整日志(DEBUG): logs/DMR-20261007.log
  （控制台已静默，只显示警告/错误；想恢复详细输出去掉 --quiet）
====================================================================
```

**Start_Render.bat 已加 `--quiet`：**
```bat
".\.venv\Scripts\python.exe" main.py --quiet
```
备份：`Start_Render.bat.bak-20261007-134708`

### 关于"有些甚至说两次"的说明

用户举例里 `苏苏没烦恼: 直播开始` 出现两次，**这不是重复日志**：

```
[06:12:25] 苏苏没烦恼: 直播开始
[07:24:18] 苏苏没烦恼: 直播开始     ← 相隔 72 分钟
```

那是**两次不同的开播**（中间断流过）。真正显得重复的是
"渲染完成 → 正在上传 → 正在清理 → 清理完成 → 上传完成"这组固定句式
每个分段都来一遍，加上 GOP/分段完成的常规信息，显得啰嗦。
降噪到 WARNING 后这些都不显示了。

### 回滚 / 调整

# 或临时用批处理不加参数跑（详细模式）
