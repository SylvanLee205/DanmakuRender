切换到 CD2 核心服务版（用户偏好，且解决闪窗问题）

【切换原因】
1. 用户更青睐服务版
2. 服务版跑在 Session 0（SYSTEM），**不弹控制台窗口** —— 解决"隔一段时间
   闪一下终端窗口"的问题
3. Windows 服务自带"失败自动重启"，不需要外部看门狗

【闪窗问题的根源（我引入的）】
看门狗计划任务必须用 LogonType=Interactive，因为 S4U 不加载用户配置文件、
无交互桌面，CD2 这种 WinUI 应用在 S4U 下起不来（实测 50 次全失败）。
但 Interactive 类型会**显示控制台窗口**，而看门狗每 5 分钟跑一次、
每次 1-2 秒 —— 就是用户看到的"隔一段时间闪一下"。
（修法本可以是 pythonw.exe 或 wscript+VBS 隐藏窗口，但切服务版一并解决了）

【两个产品最容易搞混的地方】
进程名都叫 clouddrive.exe，Get-Process CloudDrive 会同时匹配两个。
必须看路径区分：
  核心服务版: C:\Program Files\CloudDrive2\clouddrive.exe  （22.3 MB）
              经 shawl.exe 启动，LocalSystem，Session 0，端口 19798
              配置: C:\Windows\System32\config\systemprofile\Waytech\CloudDrive2\
  应用版:     C:\Program Files\CloudDrive\CloudDrive.exe   （0.3 MB）
              用户会话，端口 29798
              配置: %LOCALAPPDATA%\CloudDrive.WinUI
功能等价（同一百度账号、同一 /百度网盘 目录、都开 webdav_root="/"）。

【已完成】
1. 启动服务版并设为 Automatic，验证 WebDAV 能读云端（15 个目录）
2. ★ 验证服务版能真的上传（传 2MB 测试文件，查服务版 dir_cache.sqlite
   确认条目存在）-> ✅ 成功，日志 0 条 PermissionDenied
3. rclone 配置 29798 -> 19798
4. 停掉应用版（taskkill，注意别误杀服务版的同名进程）
5. 移除应用版开机自启（HKCU Run 键，原值备份在 .temp\）
6. 配置服务版失败自动重启：
   sc.exe failure CloudDrive2 reset= 86400 actions= restart/5000/restart/15000/restart/60000
7. 删除 CD2 看门狗任务（服务版自带自愈；且它只会去启动应用版，会打架）
   删除静默启动器 tools\run_watchdog_hidden.vbs
8. 服务版配置优化：
   - file_log_level: Error -> Info（Error 会隐藏诊断信息。2026-10-05 那次
     8427 次 errno -7 只留几条日志就是 Error 造成的）
   - max_upload_speed_kbyps: 4096 -> 0（对 WebDAV 本来就无效）
   备份在 F:\_CD2配置备份_20261005\svc_before_opt_233824\

【端到端验证结果】
  服务版:         Running / Automatic
  19798 监听:     2 个
  应用版 29798:   无监听
  rclone 读云端:  exit=0，15 个目录
  上传测试:       ✅ 成功（mkdir + create_file + 缓存有条目，0 条 PermissionDenied）

【重要：修正之前的一个错误结论】
2026-10-05 排查时看到服务版日志有 8427 次 errno: -7 疯狂重试，当时结论是
"服务版上传能力有问题，所以用应用版"。**这是错的。**
真实原因：rclone 配置指向 localhost:19798（服务版端口），但当时服务版是停的，
实际跑的是应用版（29798）—— 端口不匹配导致的混乱。
教训：两产品端口不同、配置目录不同、进程名相同，排查时必须先确认
"哪个实例在跑、rclone 指向哪个端口"。
