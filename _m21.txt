通知系统重做：修正换行格式 + 新增开播/下播通知 + 内容按行动价值取舍

【关键修复：换行格式（实测确定）】
Server酱³ 按 Markdown 解析 desp。实测四种写法：
    纯 \n            ❌ 手机列表页像换行，点进"原文"就没了
    <br>             ❌ 原样显示成 "<br>" 文本
    HTML 标签 <b>    ❌ 原样显示成 "<b>粗体</b>"
    两空格 + \n      ✅ 正确换行（Markdown 硬换行语法）
统一用 _NL = '  \n'。这是用户实测反馈的结论。

【新增：开播 / 下播手机通知】
用户："真正的价值在另一头：开播/下播时发通知"
  🔴 开播：苏苏没烦恼  ->  主播/时间/开始录制...
  ⚪ 下播：苏苏没烦恼  ->  主播/时间
实现：DMR/Task/liveevents.py
    defaultEvent() 里检测 '直播开始' -> _notify_live('start')
    onLiveEnd()                        -> _notify_live('end')
特性：
    1. 后台线程发送，不阻塞事件处理
    2. 60 秒防抖（同任务同事件），避免重复 livestart 刷爆手机
    3. 异常静默，通知失败不影响录制主流程

【启动通知内容重新取舍（按用户反馈）】
  ✗ 启动时间     -> 删。通知自带时间，用户指出重复
  ✗ 近 24h 录制  -> 删。启动时看它没有行动价值
  ✗ 正在录制     -> 删。启动瞬间必然还没开录，只会显示"暂无"
                     （用户指出："这个通知是 DMR 启动时发出的，
                      这时候应该还没录制，正在录制这个信息几乎无用"）
  ✓ 主播加载     -> 从"N 个"改成**列出实际名字**
                     （用户："32个写的我也不知道是谁"）
  ✓ 云端通道 CD2 -> 留。启动时最该确认上传通道通不通
  ✓ 磁盘剩余     -> 新增。快满了会导致录制失败，真实风险（<30GB 告警）
  ✓ 频繁重启告警 -> 留
